# ADR 0006: Versioned Public API And Stable Protected Capabilities

## Status

Accepted for the Nakafa public API boundary correction. Amended on 13 October
2026 for the school REST API and MCP server, which live on the school host and
carry their own credential. ADR 0029 owns the school integrations, and ADR 0026
owns the host.

## Context

External REST consumers need an explicit compatibility namespace that cannot
change underneath them. Nakafa deployment components also need a direct,
stable protected contract that does not accumulate public version vocabulary.

The public and protected paths previously drifted in both directions. Public
unversioned aliases duplicated `/v1`, protected routes retained `/v1`, and the
`/v1` response reported a nonexistent public major. Nakafa has only one public
REST contract, V1. The drift made ownership and terminal cleanup unclear.

Schools also need an API of their own. It carries a credential and school data,
which the public API refuses by design, so it cannot share the public host, the
public namespace, or the public bridge.

## Decision

The public REST API uses one explicit compatibility namespace:

```text
https://api.nakafa.com/v1
https://api.nakafa.com/v1/health
https://api.nakafa.com/v1/search
https://api.nakafa.com/v1/content
https://api.nakafa.com/v1/taxonomy
https://api.nakafa.com/v1/quran/{surah}
```

`https://api.nakafa.com/openapi.json` remains the unversioned discovery
document. Every resource path inside that document uses `/v1`. The shared
`NAKAFA_PUBLIC_API_PATH` owns this namespace for OpenAPI, the CLI, tests, and
documentation. The protected edge contract mirrors the value at its deployment
boundary because Vercel config validation cannot load the source-only Contents
workspace package. Exact tests must prove both values equal. The public contract
version remains within `1.x` while `/v1` is the compatibility namespace. A
breaking external contract requires a deliberate new public namespace and its
own migration decision. It must not silently redefine `/v1`.

The namespace covers response schemas as well as paths. A package release or
deployment refactor may not relabel a breaking payload as V1. Existing V1
decoders must remain valid unless a deliberate new public namespace is
introduced.

Protected Convex capabilities are stable and unversioned:

```text
/internal/agent/runtime
/internal/agent/openapi
```

These paths are deployment seams, not public consumer contracts. The Vercel
edge maps `/v1` resources to `/internal/agent/runtime` and maps
`/openapi.json` to `/internal/agent/openapi`. Protected paths must describe
capabilities, never public API versions or public filename conventions.

The protected MCP transport is a capability of the same kind:

```text
/internal/mcp
```

Effect's `McpServer` (`effect/ai`) serves that path inside the Confect HTTP
route, built for each request. Nakafa keeps the work in front of the engine
and around it: the edge secret, the exact origin allowlist, the 64 KiB body
cap, the rate limit, the CORS and cache headers, the eight methods it serves,
the discovery capabilities it declares, every tool, resource, and prompt
definition, the tool result envelopes, and the refusals that the engine would
answer with another status, code, or body. Those refusals are other methods,
non-JSON bodies, malformed and batched bodies, a predecessor protocol version,
and JSON-RPC notifications, which get `202` without a body when they carry the
protocol version header. The engine answers everything else. A refusal that the
engine words differently keeps its code and status, and its message may take the
engine's wording.

Terminal production state has no public unversioned resource aliases and no
versioned protected aliases.

## School API

Planned. The school REST API and the school MCP server live on the school's own
host, which ADR 0026 owns:

```text
https://harapan.nakafa.com/api/v1
https://harapan.nakafa.com/mcp
```

The host already names the school, so the path does not repeat it. The public
decisions above do not change. `https://api.nakafa.com/v1` and
`https://mcp.nakafa.com/mcp` stay without a key, serve public Nakafa content
only, and never accept a school path.

- The only credential the school API accepts is a bearer token. An integration
  gets its token through OAuth 2.0 client credentials, and the CLI gets one
  through device authorization on behalf of a person. ADR 0029 owns both flows
  and the rules of the token. Its OpenAPI document and the protected resource
  metadata of its MCP server hold no school data and need no token.
- `/api/v1` is a compatibility namespace in the same sense as the public `/v1`.
  A breaking change to a school path or payload needs a deliberate new namespace
  and its own decision, never a silent redefinition, and the namespace covers
  response schemas as well as paths.
- One `HttpApi` definition owns the paths, the schemas, and the OpenAPI document
  of the school API (ADR 0029). The public document stays at
  `https://api.nakafa.com/openapi.json`, served through
  `/internal/agent/openapi`, and never lists a school path.
- The protected capability paths above stay public only. The Vercel bridges of
  the public API delete the `authorization` and `cookie` request headers
  (`createAgentEdgeRoutes` in `packages/backend/agent/route.ts`), so they cannot
  carry the school API, and no school path is added to them.
- The school paths reach Convex through the web project of the school's own data
  cell, never through the public bridge and never through another cell
  (ADR 0026, ADR 0029).

## Rollout Rule

Independent Convex and Vercel deployments use expand, switch, prove, and
contract:

1. Expand the protected origin with the stable capability paths while the
   currently deployed edge destinations remain readable.
2. Switch the protected-main edge to public `/v1` and the stable protected
   capabilities.
3. Observe and prove the exact production Git SHA, Vercel deployment identity,
   response release header, OpenAPI paths, API behavior, Convex health, and
   post-switch request logs for predecessor traffic.
4. If a legitimate predecessor reader appears, trace and migrate that reader.
   Otherwise, immediately remove predecessor mounts, rollout-only tests,
   comments, and aliases in the terminal change.

The current release owner owns the observation gate. It starts after the
protected-main switch and closes when every owned production alias and consumer
points to the successor and post-switch logs contain no legitimate predecessor
reader. The gate closes on evidence, never elapsed time. A predecessor exists
only for deployment ordering and must not become a permanent compatibility
surface.

## Consequences

- Public consumers keep a clear `/v1` contract.
- Internal maintainers use stable capability names without version churn.
- CLI and OpenAPI paths derive from one public path owner.
- Public path major and reported contract major cannot intentionally diverge.
- Workspace package versions never redefine the public API namespace or
  reported contract major.
- Public V1 response schemas retain their established payload shapes.
- Unknown nested paths such as `/v1/openapi.json` reach the protected runtime
  and return the normal structured missing-endpoint response instead of
  colliding with the OpenAPI document capability.
- Every completed rollout deletes its temporary predecessor paths and tests.
- The school API has its own host, namespace, and credential. A change to it
  cannot break a public consumer, and the public bridge cannot expose school
  data.
