# ADR 0006: Versioned Public API And Stable Protected Capabilities

## Status

Accepted for the Nakafa public API boundary correction.

## Context

External REST consumers need an explicit compatibility namespace that cannot
change underneath them. Nakafa deployment components also need a direct,
stable protected contract that does not accumulate public version vocabulary.

The public and protected paths previously drifted in both directions. Public
unversioned aliases duplicated `/v1`, protected routes retained `/v1`, and the
`/v1` response reported a nonexistent public major. Nakafa has only one public
REST contract, V1. The drift made ownership and terminal cleanup unclear.

## Decision

The public REST API uses one explicit compatibility namespace:

```text
https://api.nakafa.com/v1
https://api.nakafa.com/v1/health
https://api.nakafa.com/v1/search
https://api.nakafa.com/v1/content
https://api.nakafa.com/v1/taxonomy
https://api.nakafa.com/v1/quran/{surah}
```

`https://api.nakafa.com/openapi.json` remains the unversioned discovery
document. Every resource path inside that document uses `/v1`. The shared
`NAKAFA_PUBLIC_API_PATH` owns this namespace for OpenAPI, the CLI, tests, and
documentation. The protected edge contract mirrors the value at its deployment
boundary because Vercel config validation cannot load the source-only Contents
workspace package. Exact tests must prove both values equal. The public contract
version remains within `1.x` while `/v1` is the compatibility namespace. A
breaking external contract requires a deliberate new public namespace and its
own migration decision. It must not silently redefine `/v1`.

Protected Convex capabilities are stable and unversioned:

```text
/internal/agent/runtime
/internal/agent/openapi
```

These paths are deployment seams, not public consumer contracts. The Vercel
edge maps `/v1` resources to `/internal/agent/runtime` and maps
`/openapi.json` to `/internal/agent/openapi`. Protected paths must describe
capabilities, never public API versions or public filename conventions.

Terminal production state has no public unversioned resource aliases and no
versioned protected aliases.

## Rollout Rule

Independent Convex and Vercel deployments use expand, switch, prove, and
contract:

1. Expand the protected origin with the stable capability paths while the
   currently deployed edge destinations remain readable.
2. Switch the protected-main edge to public `/v1` and the stable protected
   capabilities.
3. Observe and prove the exact production Git SHA, Vercel deployment identity,
   response release header, OpenAPI paths, API behavior, Convex health, and
   post-switch request logs for predecessor traffic.
4. If a legitimate predecessor reader appears, trace and migrate that reader.
   Otherwise, immediately remove predecessor mounts, rollout-only tests,
   comments, and aliases in the terminal change.

The current release owner owns the observation gate. It starts after the
protected-main switch and closes when every owned production alias and consumer
points to the successor and post-switch logs contain no legitimate predecessor
reader. The gate is evidence-based and has no fixed quiet period. It never
requires a 24-hour wait. A predecessor exists only for deployment ordering and
must not become a permanent compatibility surface.

## Consequences

- Public consumers keep a clear `/v1` contract.
- Internal maintainers use stable capability names without version churn.
- CLI and OpenAPI paths derive from one public path owner.
- Public path major and reported contract major cannot intentionally diverge.
- Workspace package versions never redefine the public API namespace or
  reported contract major.
- Unknown nested paths such as `/v1/openapi.json` reach the protected runtime
  and return the normal structured missing-endpoint response instead of
  colliding with the OpenAPI document capability.
- Every completed rollout deletes its temporary predecessor paths and tests.
